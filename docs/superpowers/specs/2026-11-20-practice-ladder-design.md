# แบบฝึกหัดขั้นบันไดและตัวอย่างโจทย์ทีละขั้น — Design

วันที่ 2026-11-20 · โปรเจกต์ Einstein (project-Atom, https://jap-sat.github.io/einstein-physics/)
สถานะ: ร่างเพื่อขออนุมัติ · ขอบเขต: **ช่วงที่ 1** ของงาน "พัฒนาเนื้อหาและหลักสูตร" (ช่วงที่ 2 = บทใหม่ ออกแบบแยกภายหลัง)

## 1. เจตนาและเหตุผล

ผู้ใช้คือ **นักเรียนและคนที่ยังไม่เข้าใจฟิสิกส์** เจ้าของต้องการให้ผู้ใช้ **เข้าใจฟิสิกส์ตั้งแต่พื้นฐานจนแก้โจทย์แบบประยุกต์ได้** (คำของเจ้าของ)

ตอนนี้แต่ละบทมีบทเรียนกับแบบทดสอบปรนัย 7–8 ข้อ ซึ่งวัดว่าเข้าใจแนวคิดหรือยัง แต่ไม่ได้ฝึกให้ "แก้โจทย์เองได้" เพราะ
- ปรนัยเดาได้ และไม่ได้ฝึกขั้นตอนคำนวณ
- ตัวอย่างโจทย์ในบทเรียนมีแค่ 9 ข้อจาก 35 หัวข้อ และเฉลยออกมาทั้งก้อน ผู้เรียนอ่านแล้ว "รู้สึกว่าเข้าใจ" โดยไม่ได้ลองเอง
- ไม่มีทางไต่จากง่ายไปยาก

งานนี้จึงเปลี่ยนแบบทดสอบของ 7 บทเดิมให้เป็น **แบบฝึกหัดขั้นบันได 3 ระดับ บทละ 20 ข้อ** และเติม **ตัวอย่างโจทย์ที่เปิดเฉลยทีละขั้น** ในบทเรียน

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / สิ่งที่ถือว่าล้มเหลว

**เป้าหมาย**
1. ทุกบท (mech, thermo, waves, particle, em, atom, nuclear) มีแบบฝึกหัด **20 ข้อ**: ระดับ 1 แนวคิด 7 ข้อ · ระดับ 2 คำนวณ 7 ข้อ · ระดับ 3 ประยุกต์ 6 ข้อ → รวม 140 ข้อ (ข้อเดิม 55 ข้อเกลาแล้วนับรวม)
2. ระดับ 2 เป็น **โจทย์ตัวเลขสุ่ม**: ทุกครั้งที่ทำได้ตัวเลขใหม่ คำตอบคำนวณด้วยโค้ดจากสูตร
3. ผู้เรียน **พิมพ์คำตอบตัวเลขเอง** ในระดับ 2–3 (ไม่ใช่เลือก) ตรวจแบบยอมคลาดเคลื่อนสัมพัทธ์ ±2%
4. คำตอบผิดที่เจอบ่อย (ลืมแปลงหน่วย, ลืมหาร 2, ใช้ sin แทน cos ฯลฯ) ถูกจับได้และบอกตรงจุดว่าพลาดตรงไหน
5. ระดับ 3 มีคำใบ้เปิดทีละขั้น และวิธีทำเต็ม
6. ทุกหัวข้อ (h2) ในบทเรียนมีตัวอย่างโจทย์อย่างน้อย 1 ข้อ (35 หัวข้อ) แบบเปิดทีละขั้น ("ลองคิดก่อน → ดูขั้นต่อไป")
7. จำความคืบหน้าในเครื่อง (localStorage): ข้อไหนทำถูก/ผิด ระดับไหนผ่าน และแนะนำว่าควรทำอะไรต่อ — **ไม่ล็อก** ระดับ
8. ทุกข้อผ่านวิธีตรวจของเจ้าของ: อธิบายแบบ Feynman ในมุมผู้เรียน → มุมผู้เชี่ยวชาญตรวจกับฟิสิกส์ที่ยอมรับ → แก้และวนซ้ำ และคำตอบทุกข้อถูกตรวจด้วยเทสต์อัตโนมัติ

**ไม่ใช่เป้าหมาย**
- ระบบสมาชิก เซิร์ฟเวอร์ ฐานข้อมูล กระดานคะแนน (เว็บยังเป็นเว็บนิ่งบน GitHub Pages)
- บทใหม่ (ไฟฟ้าสถิต ไฟฟ้ากระแส แม่เหล็ก/การเหนี่ยวนำ, SHM, เสียง, ของไหล) — เป็นช่วงที่ 2
- ข้อสอบจับเวลา/ข้อสอบรวมหลายบท — ภายหลัง
- เครื่องมือให้เจ้าของแก้โจทย์โดยไม่แตะโค้ด

**สิ่งที่ถือว่าล้มเหลว (ถึงจะทำงานได้)**
- โจทย์ที่แค่แทนค่าในสูตรเดียวโดยไม่ต้องเข้าใจ — ระดับ 3 ทุกข้อต้องใช้ ≥ 2 แนวคิด/ขั้น และระดับ 1 ต้องถามความเข้าใจ ไม่ใช่ถามจำสูตร
- มีฟิสิกส์ผิด หรือคำตอบผิดแม้ข้อเดียว
- ตัวเลขสุ่มที่ไม่สมจริง (รถวิ่ง 900 m/s, มุม 89.9°) หรือทำให้คำตอบเป็นศูนย์/ติดลบ/ไม่นิยาม
- ระบบตรวจตัดสินคำตอบที่ถูกว่าผิด เพราะรูปแบบการพิมพ์ (เช่น "2.1e-2", "0,021", "2.1×10^-2")

## 3. ข้อจำกัด

- โครงเว็บเดิม: classic script ไม่มี bundler, globals, Tailwind 3 prebuilt (`npm run build:css` เมื่อใช้คลาสใหม่), MathJax 3.2.2 tex-svg (ห้ามใส่ภาษาไทยใน `\text{}`), ฟอนต์ Inter / IBM Plex Sans Thai, ตัวเลขที่เปลี่ยนได้ใช้ JetBrains Mono (คลาส `.mono`)
- เปิดจากไฟล์ในเครื่อง (file://) ได้ — ห้าม fetch ไฟล์ข้อมูล
- ธีมสว่าง/มืด (`html.dark`), localStorage ผ่าน `store.get/set` (prefix `einstein_`)
- เส้นทาง URL เดิม `#<id>-quiz` ต้องยังใช้ได้ (ลิงก์ที่น้อง ๆ อาจบันทึกไว้)
- ภาษาไทยทั้งหมด · หน่วยของช่องคำตอบใช้หน่วยที่บทนั้นใช้ตามปกติ (m, cm, nm, eV, MeV, u, °C, kJ ฯลฯ — แสดงหลังช่อง) ไม่บังคับ SI ล้วน *(การตัดสินใจของผู้สร้าง)* · ค่าคงที่และค่า g ระบุในโจทย์ทุกครั้ง
- มือถือจอ 390 px ต้องใช้ได้ (ช่องพิมพ์ตัวเลขเปิดคีย์บอร์ดตัวเลข)

## 6. การออกแบบ

### 6.1 ประสบการณ์ผู้เรียน

แท็บ "แบบทดสอบ" ของแต่ละบทเปลี่ยนชื่อเป็น **"แบบฝึกหัด"** (URL `#<id>-quiz` เดิมยังใช้ — การตัดสินใจของผู้สร้าง เพื่อไม่ทำลายลิงก์)

หน้าแรกของแท็บ = **แผนที่ระดับ**:

```
แบบฝึกหัด · กลศาสตร์
┌ ระดับ 1 · เข้าใจแนวคิด     ●●●●●○○  5/7   [ทำต่อ]
├ ระดับ 2 · คำนวณ           ●●○○○○○  2/7   [เริ่ม]     ← แนะนำ
└ ระดับ 3 · โจทย์ประยุกต์    ○○○○○○   0/6   [เริ่ม]
                                     [ทำข้อที่ยังผิด (3)]
```

- จุดแต่ละจุด = ข้อ (เขียว = ถูกแล้ว, แดง = เคยผิดและยังไม่ถูก, เทา = ยังไม่ทำ)
- "แนะนำ" = ระดับแรกที่ถูกยังไม่ถึง 70% (ไม่ล็อก กดระดับไหนก็ได้)
- "ทำข้อที่ยังผิด" = ชุดทบทวนเฉพาะข้อที่สถานะยังเป็นผิด

**หน้าข้อ (ปรนัย ระดับ 1)**: เหมือนเดิม (สลับตัวเลือก, ตรวจ, เฉลย) แต่ **ทุกตัวเลือกที่ผิดมีคำอธิบายเฉพาะ** ว่าคนที่เลือกข้อนี้มักเข้าใจผิดตรงไหน (field `why` ต่อตัวเลือก) — แสดงคำอธิบายของตัวเลือกที่เลือก + คำอธิบายข้อถูก

**หน้าข้อ (ตัวเลข ระดับ 2–3)**:

```
ระดับ 2 · ข้อ 3/7                                    ●●○○○○○
ลูกบอลถูกขว้างขึ้นตรง ๆ ด้วยความเร็ว 12 m/s จะขึ้นไปได้สูงสุดกี่เมตร (g = 9.8 m/s²)
[ 7.35         ] m        [ตรวจคำตอบ]
✗ 14.7 m — ดูเหมือนลืมหารด้วย 2 ใน v² = 2gh  ลองใหม่ได้
[คำใบ้ 1/2]  [ดูวิธีทำ]                         [ข้ามข้อนี้]
```

- พยายามได้ไม่จำกัด; ผลที่บันทึก = **ถูกในครั้งแรกโดยไม่ดูวิธีทำ** หรือ "ถูกหลังพยายาม/ดูคำใบ้" (ทั้งสองนับว่า "ถูก" ในแผนที่ แต่แยกสถิติ) · ดูวิธีทำแล้ว = ข้อนั้นยังไม่นับว่าถูก จนกว่าจะทำ **ตัวเลขชุดใหม่** ถูก (ระดับ 2) หรือกลับมาทำถูกในรอบถัดไป (ระดับ 3)
- ระดับ 2: ปุ่ม **"ตัวเลขชุดใหม่"** หลังทำถูก/ดูวิธีทำ
- ช่องหน่วยแสดงหลังช่อง (ผู้เรียนไม่ต้องพิมพ์หน่วย)
- ตัวเลขที่แสดงในโจทย์ใช้ `.mono`
- วิธีทำเต็ม = ขั้นตอนพร้อมสมการ (MathJax) และตัวเลขของชุดนั้นจริง ๆ

**ตัวอย่างโจทย์ในบทเรียน** (แทน `<details class="ex">` เดิม 9 ข้อ + เพิ่มให้ครบ 35 หัวข้อ):

```
┌ ตัวอย่าง · ปล่อยลูกบอลจากที่สูง 20 m จะใช้เวลาเท่าใดจึงถึงพื้น (g = 10 m/s²)
│ ลองคิดเองก่อน แล้วค่อยเปิดทีละขั้น
│ ขั้นที่ 1  รู้อะไรบ้าง: u = 0, s = 20 m, a = g = 10 m/s²  หา t
│ ขั้นที่ 2  เลือกสมการที่มี u, s, a, t:  s = ut + ½at²
│ [ดูขั้นต่อไป]                                   ขั้น 2/4
└
```

ตัวอย่างโจทย์เป็นแบบตายตัว (ไม่สุ่ม) เขียนเป็น HTML ใน `<template id="lec-…">` เดิม

### 6.2 ข้อมูล (data model)

ไฟล์ใหม่ต่อบท `assets/js/data/practice/<id>.js` (7 ไฟล์) ลงทะเบียนเข้า global `PRACTICE[<id>] = [ ...items ]` โหลดใน `index.html` ต่อจาก `quiz.js` และ `quiz.js` เดิมถูกยุบเข้าไฟล์เหล่านี้ (ข้อเดิมย้ายเป็น item ระดับ 1/2/3 ตามความยาก)

item ทุกชนิดมี `id` คงที่ (เช่น `mech-2-03`) เพื่อใช้เป็นคีย์ความคืบหน้า — ห้ามเปลี่ยนหลังเผยแพร่

```js
// ระดับ 1: ปรนัย
{ id, level: 1, type: 'mcq', q, options: [{ t, why }], a /* index ข้อถูก */, e /* คำอธิบายข้อถูก */ }

// ระดับ 2: ตัวเลขสุ่ม
{ id, level: 2, type: 'num',
  gen(rng) → vars,                 // สุ่มค่าในช่วงที่สมจริง ปัดเลขนัยสำคัญตามที่แสดง
  q(vars) → string,                // ข้อความโจทย์ (MathJax ได้)
  answer(vars) → number, unit,     // คำตอบในหน่วยที่ช่องแสดง (unit)
  tol = 0.02,                      // ค่าคลาดเคลื่อนสัมพัทธ์
  mistakes: [{ value(vars) → number, msg }],   // คำตอบผิดยอดนิยม
  hints: [string | (vars) → string],
  solution(vars) → string }        // วิธีทำเต็มด้วยตัวเลขชุดนั้น

// ระดับ 3: ตัวเลขตายตัว หลายขั้น
{ id, level: 3, type: 'num', q, answer, unit, tol, mistakes: [{ value, msg }], hints: [...], solution }
```

- `rng` = ตัวสุ่มที่ใส่ seed ได้ (เพื่อเทสต์ซ้ำได้) — ในหน้าเว็บ seed จาก `Math.random()`
- ระดับ 3 อาจมีหลายช่องคำตอบได้ (`parts: [{ label, answer, unit }]`) — ผู้สร้างตัดสินว่าข้อไหนจำเป็น

### 6.3 การตรวจคำตอบตัวเลข

`parseAnswer(str) → number | null` รองรับ: `0.021`, `.021`, `2.1e-2`, `2.1E-2`, `2.1×10^-2`, `2.1x10^-2`, `2.1*10^-2`, `2.1 × 10⁻²` (ตัวยก), ช่องว่าง, จุลภาคเป็นตัวคั่นหลักพัน (`12,000`) และ `−` (minus ยูนิโค้ด) · ถ้าแปลงไม่ได้ แจ้ง "อ่านตัวเลขไม่ออก ลองพิมพ์แบบ 2.1e-2" (ไม่นับเป็นผิด)

ถูก ⇔ |x − ans| ≤ tol·|ans| · ตรวจ `mistakes` ด้วยเกณฑ์เดียวกัน (ถ้าตรงกับ mistake → แสดง msg) · ค่า mistake ที่ใกล้คำตอบถูกเกิน tol ห้ามมี (เทสต์จับ)

### 6.4 สถานะของแต่ละข้อ *(การตัดสินใจของผู้สร้าง)*

สถานะ = ผลของ **ความพยายามครั้งล่าสุดที่จบแล้ว** (ไม่ใช่ครั้งที่ดีที่สุด) เพื่อให้แผนที่บอกความชำนาญปัจจุบันตามจริง

| สถานะ | จุด | เกิดเมื่อ |
|---|---|---|
| ยังไม่ทำ | เทา | ไม่เคยตรวจคำตอบ |
| `ok` | เขียว | ตอบถูกโดยไม่เปิดคำใบ้/วิธีทำ และ (ระดับ 2–3) ในการพิมพ์ ≤ 2 ครั้ง |
| `ok-help` | เขียวอ่อน | ตอบถูกหลังเปิดคำใบ้ หรือพิมพ์ > 2 ครั้ง |
| `wrong` | แดง | ระดับ 1 เลือกผิด · ระดับ 2–3 เปิด "ดูวิธีทำ" ก่อนตอบถูก หรือกด "ข้ามข้อนี้" หลังตอบผิด |

- ระดับ 1: ตอบได้ครั้งเดียวต่อรอบ (เหมือนเดิม) แล้วแสดงเฉลย · รอบถัดไปของระดับ = ทำใหม่ได้
- ระดับ 2: หลังดูวิธีทำ กด "ตัวเลขชุดใหม่" แล้วตอบถูก → สถานะเปลี่ยนตามกฎข้างบน
- ระดับ 3: หลังดูวิธีทำในรอบนั้น ช่องคำตอบถูกปิดจนกว่าผู้เรียนจะออกจากข้อ (ไปข้อถัดไป/ออกจากระดับ) — ทำใหม่ได้ใน **รอบถัดไปของระดับ** (เริ่มระดับใหม่จากแผนที่) เพื่อไม่ให้พิมพ์ตามเฉลยทันที
- ถ้าข้อที่เป็น `ok` ถูกตอบผิดในรอบหลัง → เป็น `wrong`
- "ผ่านระดับ" (ใช้คำนวณ "แนะนำ") = จำนวน `ok` + `ok-help` ≥ 70% ของข้อในระดับ · เมื่อผ่านครบทุกระดับ แนะนำ "ทำข้อที่ยังผิด" ถ้ามี ไม่งั้นแนะนำบทถัดไป

### 6.5 ความคืบหน้า

คีย์ `einstein_practice_<id>` = `{ v: 1, items: { [itemId]: { s: 'ok' | 'ok-help' | 'wrong', n: attempts, t: lastTimestamp } } }` (มีเลขเวอร์ชันเผื่อย้ายรูปแบบภายหลัง) · คะแนนเดิม `best_<id>` บนหน้าแรกเปลี่ยนไปอ่านจากคีย์ใหม่ · เขียนเมื่อตรวจคำตอบ · อ่านเพื่อวาดแผนที่ระดับ · ปุ่ม "ล้างความคืบหน้าบทนี้" (ยืนยันก่อน) ที่ท้ายแผนที่

ตัวเลข "x ข้อพร้อมเฉลย" บนการ์ดท้ายบทเรียน (`app.js`) เปลี่ยนเป็น "แบบฝึกหัด 20 ข้อ · ทำถูกแล้ว n"

### 6.6 การตรวจความถูกต้อง (บังคับ)

เทสต์ Node (`tests/practice.test.js`) สำหรับทุกข้อทุกบท:
- จำนวนข้อ 20 ต่อบท และสัดส่วน 7/7/6 · `id` ไม่ซ้ำ รูปแบบถูก
- ระดับ 2: สุ่ม 500 ชุดต่อข้อ (seed คงที่) → คำตอบเป็นจำนวนจริงจำกัด ไม่เป็นศูนย์ อยู่ในช่วงสมจริงที่ข้อนั้นประกาศ (`range`), ทุก `mistakes` ห่างจากคำตอบถูก > 2·tol, `q/solution` ไม่มี `undefined`/`NaN`
- `solution(vars)` ระบุคำตอบตัวเลขเดียวกับ `answer(vars)` (ภายใน tol)
- ระดับ 1: ทุกตัวเลือกผิดมี `why`, ตัวเลือกไม่ซ้ำกัน
- `parseAnswer` กับรูปแบบทั้งหมดใน 6.3
- ตรวจคำตอบโดยแยกอิสระ: สำหรับข้อระดับ 2/3 ผู้สร้างเขียนคำตอบอ้างอิงด้วยการคำนวณแยกจากฟังก์ชันใน item (เช่น ตารางค่าอ้างอิงที่คำนวณด้วยมือ/สคริปต์ต่างหากสำหรับ seed คงที่ 3 ชุด) — กันกรณีสูตรใน `answer` ผิด

เทสต์เบราว์เซอร์ (Playwright, harness เดิม): แผนที่ระดับ, ปรนัยแสดง `why`, ช่องตัวเลขตรวจถูก/ผิด/mistake/อ่านไม่ออก, คำใบ้ทีละขั้น, ตัวเลขชุดใหม่, ความคืบหน้าคงอยู่หลังรีโหลด, ตัวอย่างโจทย์เปิดทีละขั้น, มือถือ 390 px, ธีมมืด, ไม่มี page error, MathJax ไม่มีภาษาไทยใน `\text{}`

การตรวจเนื้อหาแบบมนุษย์: ทุกข้อผ่าน Feynman (มุมผู้เรียน) + ผู้เชี่ยวชาญ (มุมฟิสิกส์) ตามวิธีของเจ้าของ บันทึกผลตรวจในไฟล์ `docs/superpowers/content-review/<id>.md` (สั้น ๆ: ข้อไหนแก้อะไร)
